## 1. 业务概述

一个面向个人投资者的 **A 股数据获取 → 存储 → 分析 → 模拟 → 可视化** 一体化平台，
核心业务主题围绕「**红利（分红）投资**」展开：

- **数据采集**：从东方财富 / TickFlow / AKShare 多数据源拉取 A 股日 K 行情
  （不复权/前复权/后复权三口径）、分红明细、个股核心指标，落 MySQL 持久化。
- **分析工具**（CLI，10 项）：红利再投、红利再投增强版、大跌分批买入、分红目标测算、
  分红后涨跌统计、星期涨跌分析、节日涨跌分析、波动分析、线性回归、模拟持仓。
- **Web 应用**（11 个页面）：股票列表/详情（K线）、星期/节日涨跌分析、红利再投模拟、
  分红目标测算、大跌买入模拟、数据导入/导出、模拟交易账户、数据管理。
- **模拟交易**：账户式模拟（买入/卖出/持仓/佣金印花税配置/成交历史）。
- **教学脚本**：随机事件驱动股价模拟、四种随机漫步对比。

典型业务问题：「长期红利再投能多赚多少？」「从高点跌 20% 抄底 + 红利再投收益如何？」
「每年想拿 X 元分红需要多少本金？」「除息后 5 日下跌概率多大？」「星期几容易涨？」

### 2.1 技术栈

| 层 | 技术 |
|---|---|

## 3. 数据模型（backend/models.py，10 张表）

| 表 | 用途 | 备注 |
|---|---|---|
| `stock_daily_quote` | 日 K（code+date 唯一）：OHLC/volume/amount + 前复权 4 列 + 后复权 4 列 | 复权价现由 data_fetcher 直接拉取填充 |
| `stock_info` | 股票代码/名称/市场(SH/SZ) | |
| `stock_dividend_detail` | **新管线**分红明细（东财 RPT_SHAREBONUS_DET，17 字段） | 分析工具与 `/api/dividend-reinvest` 读它 |
| `stock_dividend_events` | **旧管线**分红事件表 | 仅旧脚本 divide_importer.py 写入；唯一活读者是 `/api/stocks/{code}/dividends`（双轨问题，见 §8） |
| `stock_core_data` | 核心指标快照（市值/PE/PB/ROE/营收等 + data_source_type） | |
| `stock_cookies` | 东财可用 Cookie 池（fail_count） | |
| `stock_weekday_stats` | 个股按星期几的涨跌统计结果 | |
| `simulation_account` / `simulation_position` / `simulation_trade` | 模拟账户/持仓/成交 | 佣金、印花税率可调 |

## 4. 后端 API（全部前缀 /api，9 个 router）

| Router | 端点要点 |
|---|---|
| stocks | 列表/搜索/同步；`POST /{code}/fetch` 拉行情；`/quotes` K线分页；`/stats`；`/core-data`；`/dividends`（旧表）+ `/dividend-details`（新表）；星期统计计算与查询 |
| data | `POST /fetch` 批量拉取（**遗留**，与 import/quotes 重叠） |
| holiday | `GET /analysis` 节日前后涨跌（依赖 public_data 假日 JSON） |
| import_data | `POST /quotes` 批量导入；`POST /basic-info`；`GET /datasource` |
| simulation | 账户查询/买/卖/成交历史/重置/费率配置 |
| export_data | `POST /sql` 后台导出全库 SQL + 进度轮询 + 下载 |
| dividend_reinvest | 分红明细查询/同步；`POST /{code}/simulate` → strategy_runners.run_dividend_reinvest |
| dividend_target | `POST /{code}/plan` → strategy_runners.plan_target |
| dip_buy | `POST /{code}/simulate` → strategy_runners.run_dip_buy |

`main.py`：lifespan 建表、CORS 全开、全局异常处理、`GET /api/health`。

## 6. CLI 分析体系（analysis/ + 股票分析.py）

统一入口 `python3 股票分析.py <功能> [参数]`，无参数进交互菜单。
10 个工具的实现契约与红利再投家族详情见《红利再投系列工具-功能与技术文档.md》；要点：

- `analysis/tools/` 每工具 5 个入口符号（ANALYSIS_NAME/DESCRIPTION/add_parser/run/interactive_input）；
  `TOOLS` 注册表只存字符串，import 零副作用，build_parser 时懒加载。
- 公共层：`cli.py`（父解析器/ask）、`report.py`（报告版式，字节级约定）、
  `chart_utils.py`（绘图块）、`data_access.py`（DB 装配）、`trading_calendar.py`（交易日历，
  读 public_data/cn_holidays）、`metrics.py`（回撤/年化）。
- `_reinvest_common.py`（2026-09-07 新增）：红利再投家族三工具的报告节/图表骨架/run 骨架。
- 输出契约：`results/{功能名}/{yyyymmdd}/{功能名}_{code}_analysis_log.txt` + jpg 图表，
  控制台与日志双写，**字节级不得变更**。
- `simulation/strategy_runners.py` 双路径：log=None=web（静默）、log≠None=CLI（打日志，
  空行情返回 no_data）。

## 8. 已知问题汇总（详见《项目重构方案.md》）

1. **表名双轨**：分红 `stock_dividend_events`(旧)/`stock_dividend_detail`(新) 并存；
   `/api/stocks/{code}/dividends` 仍读旧表（旧表只喂过 601857），Web 个股页分红数据对其他股票为空。
2. **凭据明文**：`emdata/tickflow_reader.py:25` API key 硬编码默认值；`tickflow方式.md` 明文 key；
   `backend/db_config.py` 默认口令 `123456`；`emdata/config.py` 种子 Cookie。
3. **旧版脚本 4 个 + 残留数据**（quote_saver/divide_importer/get_adjust_price/模拟持仓2/temp JSON）与
   现役管线并存，文档与注释存在过时引用。
4. **backend**：services.py 1093 行多职责；services↔data_fetcher 函数级互 import（准循环）；
   sys.path 注入散落 5 处；EXPORT_TABLES 漏 `stock_dividend_detail`；EASTMONEY_DEFAULT_* 死常量；
   导出任务状态在内存（重启丢失）；CORS 全开。
5. **frontend**：baseURL 硬编码；vue-echarts 冗余依赖 + echarts 全量引入；
   7 处搜索防抖/3 处图表初始化复制粘贴（StockPicker 未复用）；KLineChart 双生命周期钩子；
   setTimeout 渲染 hack；无全局错误处理。
6. **运行环境**：项目实际运行 Python 3.10（曾混入 3.12+ f-string 导致入口瘫痪，2026-09-07 已修复）；
   MySQL 依赖本机 OrbStack 容器手动启动。
7. **历史兼容包袱**：2008 年假日 JSON 旧格式被静默跳过；`routers/data.py` 遗留端点。

## 9. 关键设计契约（重构红线）

1. `results/` 目录与文件命名契约不变；CLI 日志**字节级一致**（时间戳除外）。
2. Web/CLI 双路径行为契约（strategy_runners 的 log 参数语义）不变。
3. API 端点路径与响应结构不变（前端无测试，靠人工核对）。
4. 数据表结构不变（本次只做代码层重构，不做 schema 迁移）。
5. Python 3.10 语法兼容。
